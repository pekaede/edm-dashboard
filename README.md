# 品牌营销触达趋势看板

基于 Milled 多站点邮件数据的竞品 EDM 调研看板，用于查看邮件触达节奏与主题分布（含服务/法务通知）。

技术栈：React + Vite + TypeScript + Tailwind CSS。

## 功能

- **全局站点**：顶部选择器默认美国（US），联动看板、OnePage、邮件列表、日历与词云；跨市场对比保留独立多选，不受全局站点影响。
- **数据看板（`#dashboard`）**：KPI、品牌 / 主题 / 周分布图表及关键洞察，均按当前站点实时聚合。
- **词云**：支持三周（默认）与三个月窗口切换。
- **日历热力图**：按月展示，使用覆盖整个三个月窗口的全局色阶，支持品牌筛选与关键词搜索。
- **邮件视图（`#emails`）**：独立页面，支持品牌 + 主题组合筛选；点击看板主题分布环形图可跳转，并预选对应主题。
- **OnePage 报告（`#report`）**：从同一批逐封记录实时生成当前站点的品牌周分布、主题占比、品牌日频与关键词；无邮件时显示空态，不加载冻结报告。

## 数据说明

数据来源为 **Milled**，共配置美国（US）、英国（UK）、澳洲（AU）、法国（FR）、德国（DE）、意大利（IT）、荷兰（NL）、西班牙（ES）8 个市场，当前 7 个市场已有收录记录，西班牙（ES）暂无记录。各市场样本量的差异源于 Milled 各市场品牌页的收录覆盖，不代表品牌实际发送量的差异。共 6 个品牌：Zara、lululemon、ALO Yoga、Halara、Temu、SHEIN；不保证各站点均覆盖全部品牌。

| 窗口 | 日期范围 | 邮件样本数 |
| --- | --- | --- |
| 三周（默认） | 2026-10-07–2026-10-28 | 当前站点窗口内逐封动态计数（默认 US），不使用历史冻结数 |
| 三个月 | 2026-07-28–2026-10-28 | 当前站点逐封动态计数；全市场完整性以相同查询窗口的 Supabase 精确总数校验 |

数据看板的 KPI 与品牌 / 主题 / 周分布图表使用三周口径；词云可切换窗口，日历热力图和邮件视图使用三个月数据。OnePage 同时列出三周概览与三个月补充统计，分别标明窗口。日期查询截止 2026-10-28，由每日更新任务在成功后推进，窗口随之滑动并保持 93 天；聚合器可随经确认后扩展的查询窗口重新分桶，两者不可混淆。

计数为 Milled 品牌页在对应窗口内可见的收录邮件数，**不是品牌全量发送量**。每封邮件只归一个主题；词频按“含该词的邮件数”统计，同一封邮件内同词重复只计一次。

## 本地运行

```bash
npm install
npm run dev
```

在本地 `.env` 中配置 `VITE_SUPABASE_URL`、`VITE_SUPABASE_PUBLISHABLE_KEY` 和 `VITE_EDM_DATA_SOURCE=supabase`；环境文件不纳入版本管理。部署时在构建环境中配置相同变量，修改后需重启开发服务或重新构建。

## 回归检查

使用 Node.js 24+ 的内置 `node:test`，复用现有 TypeScript 依赖在内存中转译被测源文件。测试在同一进程运行，无新增依赖、无构建产物，也不访问网络或读取 `.env`。

```bash
npx tsc -b
npm test
```

`tests/` 覆盖数据窗口起止、含首尾天数与分桶边界、URL 状态往返、CSV 公式注入中和，以及 Banner 的 8 类构图与 23 个季节标签契约。日期断言固定当前窗口；经确认滑动窗口时，应同步更新测试中的日期与预期分桶。

## 构建

```bash
npm run build
```

产物在 `dist/`。

构建同时预渲染首页介绍、生成 8 个中文市场落地页（`/markets/us/` 等）及 `dist/sitemap.xml`，无新增依赖。首页与 React 共用简介组件，启动后原位接管；市场页复用全站样式与分享标签，不加载 SPA 脚本。生成型 SEO 文案 v1 仅中文，不随看板语言切换。

构建环境沿用 `VITE_SUPABASE_URL` 与 `VITE_SUPABASE_PUBLISHABLE_KEY`，以公开只读 `HEAD` 查询当前 `LIVE_WINDOW` 内各市场的精确邮件计数。缺配置、网络失败、响应缺少精确总数或 JSON 回滚模式时不展示数字；零样本市场显示“持续收录中”。计数标注构建日期与查询窗口，重新构建才会更新。sitemap 的 `lastmod` 使用构建环境 UTC 日期，首页 daily、市场页 weekly；不再维护 `public/sitemap.xml`。

构建后执行独立产物自验：

```bash
node scripts/verify-seo.mjs
```

实现、测试、产物核验及环境限制见 [SEO 实施结果](reports/seo-implementation.md)。

## 更新数据

`src/data.ts` 仅作为品牌 / 主题顺序、标签等结构定义及历史资料；当前页面不使用其冻结计数或 US 编辑结论。KPI、图表、洞察、品牌弹窗、OnePage 与词云均从共享逐封数据按所选站点聚合。

逐封记录默认由 `src/supabase.ts` 只读查询，经 `src/email-data.ts` 统一模型、共享缓存与完整性校验后供所有视图使用。查询窗口为 2026-07-28–2026-10-28，不硬编码预期样本总数。加载时先读取 PostgREST OpenAPI 的主键标注，优先使用数据库主键稳定排序；主键元数据不可用时直接使用市场、品牌、日期、源索引、日内序号的完整复合键进行排序与身份校验。所有选定标识均须通过全量唯一性检测。分页前后及每页以 `count=exact` 核对总数，同时检测跨页重复；重复、总数变化或未取齐时丢弃本轮结果，最多尝试三次，仍失败则报错并支持共享重试。仅完整且唯一的数据进入 ready，日历沿用该数据源或当前站点的完整性口径。

本地回滚时设置 `VITE_EDM_DATA_SOURCE=json` 并重启或重新构建，才会懒加载 `src/email-data-json.ts` 和六份历史 US 逐封 JSON。该源显式标注为历史美国快照，每条记录标记 US；完整性按六份文件自身的有效记录数校验，不与 live 多市场总数比较。仅 Temu 的商家侧 `other` 被排除，其他品牌的服务/法务通知保留；非 US 站点显示空态。Supabase 构建不包含这些 JSON。更新时需核对时间窗口、数据源与统计口径，不覆盖历史资料。
